# 需求转功能点工作流

当用户提供需求描述时，**必须按以下流程执行**，不要直接开始写代码。

## 流程概览

```
用户输入需求
    ↓
分析需求，识别功能类型
    ↓
提取功能点，分类整理
    ↓
向用户展示功能点清单
    ↓
等待用户确认
    ↓
确认后才开始生成代码
```

## 第一步：需求分析

### 识别需求类型

根据用户描述，判断需求属于哪种类型：

| 需求类型 | 关键词 | 典型功能点 |
|---------|-------|-----------|
| 列表页 | 列表、查询、搜索、筛选 | 筛选区、数据列表、分页、操作按钮 |
| 详情页 | 详情、查看、展示 | 信息展示、状态标签、操作按钮 |
| 表单页 | 新增、编辑、创建、提交 | 表单字段、校验规则、提交/保存 |
| 弹窗 | 弹窗、对话框、确认 | 弹窗内容、确认/取消按钮 |
| 复杂页面 | 多模块、Tab、步骤 | 多个子模块、切换逻辑、数据联动 |

### 提取关键信息

从需求中提取：
- **业务实体**：操作的对象是什么（用户、订单、活动等）
- **操作类型**：增删改查、状态变更、导入导出等
- **交互方式**：按钮点击、表单提交、开关切换等
- **数据展示**：列表、卡片、表格、详情等
- **特殊要求**：权限控制、数据校验、状态流转等

## 第二步：功能点分类

### 分类模板

将功能点按以下类别整理：

```markdown
## 功能点清单

### 📋 页面展示
- [ ] X.X 页面整体布局
- [ ] X.X 头部/标题区域
- [ ] X.X 筛选/搜索区域
- [ ] X.X 内容展示区域
- [ ] X.X 分页/加载更多

### 🔄 交互功能
- [ ] X.X 搜索/筛选操作
- [ ] X.X 新增/创建操作
- [ ] X.X 编辑/修改操作
- [ ] X.X 删除/禁用操作
- [ ] X.X 状态切换操作

### 📡 数据处理
- [ ] X.X 数据加载（列表/详情）
- [ ] X.X 数据提交（新增/编辑）
- [ ] X.X 数据校验
- [ ] X.X 错误处理

### 🎨 状态展示
- [ ] X.X 加载中状态
- [ ] X.X 空数据状态
- [ ] X.X 错误状态
- [ ] X.X 操作反馈（成功/失败提示）

### 🔐 权限控制（如有）
- [ ] X.X 按钮权限
- [ ] X.X 数据权限
- [ ] X.X 页面权限
```

### 功能点编号规则

- 使用 `大类.序号` 格式，如 `1.1`、`2.3`
- 大类按展示顺序排列
- 同类功能点按重要性排序

## 第三步：展示并确认

### 展示模板

```markdown
## 功能点清单

根据你的需求「{需求描述摘要}」，我梳理出以下功能点：

### 📋 页面展示
- [ ] 1.1 {功能点描述}
- [ ] 1.2 {功能点描述}

### 🔄 交互功能
- [ ] 2.1 {功能点描述}
- [ ] 2.2 {功能点描述}

### 📡 数据处理
- [ ] 3.1 {功能点描述}

### 🎨 状态展示
- [ ] 4.1 {功能点描述}

---

**请确认以上功能点是否符合预期？**

1. ✅ **确认，开始生成代码**
2. ➕ **需要添加功能点**（请说明要添加什么）
3. ➖ **需要删除某些功能点**（请说明序号）
4. ✏️ **需要修改功能点描述**（请说明序号和新描述）
5. 🔄 **需要调整优先级**（请说明调整方式）
```

### 等待确认

**重要：必须等待用户明确确认后才能开始生成代码！**

用户可能的回复：
- "确认" / "可以" / "开始" → 开始生成代码
- "添加 XXX" → 补充功能点后重新展示
- "删除 2.3" → 移除功能点后重新展示
- "修改 1.2 为 XXX" → 更新功能点后重新展示

## 第四步：功能点细化（可选）

对于复杂功能，可以进一步细化：

### 表单功能细化

```markdown
### 📝 表单功能细化

**2.1 新增表单**
- 字段：名称（必填）、类型（下拉）、描述（可选）
- 校验：名称不能为空、名称不能重复
- 提交：调用新增接口、成功后刷新列表

**2.2 编辑表单**
- 数据加载：根据 ID 获取详情
- 字段：同新增
- 提交：调用编辑接口、成功后刷新列表
```

### 列表功能细化

```markdown
### 📋 列表功能细化

**1.3 数据列表**
- 展示字段：名称、状态、创建时间、操作
- 排序：按创建时间倒序
- 操作：编辑、删除、启用/禁用

**1.4 分页**
- 每页条数：10/20/50 可选
- 显示总数
- 页码跳转
```

## 注意事项

1. **不要跳过确认步骤** - 必须等用户确认后才生成代码
2. **功能点要具体** - 避免模糊描述，如"处理数据"应改为"调用 XX 接口获取列表数据"
3. **考虑边界情况** - 空状态、错误状态、加载状态都要列出
4. **保持可追溯** - 功能点编号便于后续沟通和修改
5. **适度细化** - 简单需求不需要过度拆分，复杂需求要充分细化
